# SC1-A native socket qualification

This is a bounded qualification client for omnet issue #3, not a second daemon, store, TKA implementation, checker or signer. All new executable test and runner logic is Omega. The existing JSON, codec and BLAKE2s units are reused; the observer does not call the daemon's state loader or store reader.

Base: `feat/tkad-service` at `1e075776855d4389b69b23b54b49ed230d488717`. The original IPC expectations are in `contract.txt`; its amendment records SC1 revision 2 and the integrator-requested candidate comparison. Source/compiler/binary/fixture identities, exact run outcomes, measurement samples and actual persisted bytes are under `evidence/`.

## Reproduce with synthetic data

Run from this repository's root on Linux AArch64:

```sh
sh tools/omc.sh
build/omega-mv/seed/out/omc < qualification/security3/run.om > build/security3-run
chmod 700 build/security3-run
build/security3-run "$PWD/build/omega-mv/seed/out/omc"
```

The first command verifies the repository compiler pin. The remaining commands bootstrap the Omega coordinator; they are not a new shell test runner. `run.om` invokes the existing `tools/build-tkad.sh`, concatenates the client with the existing library units, compiles it and the thin syscall-wrapper fault variants, forks the real daemon and clients, checks exact child exit statuses, and retains per-process raw logs and state under `build/security3/`. The daemon only uses newly created private directories and local Unix sockets. No installed daemon, network configuration or GPU is touched.

An optional second argument supplies an independently built candidate daemon:

```sh
build/security3-run "$PWD/build/omega-mv/seed/out/omc" /absolute/path/to/candidate/tkad
```

Mode 0 is the original daemon. Modes 1, 2 and 3 are respectively short-write, ENOSPC and post-rename directory-fsync EIO variants of the **base**, not the candidate. Mode 4 is a completed-result observer control: the real one-AUM snapshot is deliberately compared with expected count two. It must exit normally with status 41 and `FAIL assertion 202`; compilation failure, signal, timeout or a different assertion does not count. Optional mode 5 repeats the real service scenario against the candidate and additionally requires no Revision change on an already-retained AUM replay.

The synthetic keys and secret come only from the existing `cmd/tkad/test/fixture.json`. That fixture was generated by the owner's pinned Tailscale oracle. This lane consumes it unchanged; it does not generate new signing keys or reproduce the full crypto differential suites.

### What the demonstration does

1. Register two fixture nodes and activate their signed genesis, including the synthetic support-disablement secret.
2. Send wrong relay IDs/keys, missing admin, unknown route, invalid signatures, stale interactive head, malformed/trailing/duplicate JSON and malformed/truncated/oversized framing. Check the specified refusals and unchanged persisted authority.
3. Fork two clients. Each builds its request before reporting readiness through a pipe. Release A to send the signed update and close without reading the acknowledgement. Reconcile the map and actual snapshot. Only then release B to replay the same AUM. Both processes must exit normally; retained AUM count stays two.
4. Prepare another node-2 request in a forked client, remove node 2 through the real socket, then release that client. Its request must get 403. This tests serialization before admission, not revocation inside a handler.
5. Append the typed-empty-metadata and key-removal fixtures. The old node signature then gets 403, and restart retains the authority history and expected head.
6. Test the disclosure policy separately: active bootstrap returns exactly the genesis and no disablement secret; missing admin, wrong secret and stale head refuse; successful disablement intentionally changes bootstrap to exactly the synthetic disablement secret. Restart preserves that disclosure. These are output-policy checks, not constant-time or timing-noninterference evidence.
7. Exercise the owner's `stwr`/`stsync` syscall seams in separately compiled binaries. Seven-byte writes still complete. Injected ENOSPC returns 503 without publication and allows the next mutation. Injected post-rename directory-sync EIO must produce no response and exact exit 74; restart recovers the renamed candidate.

The snapshot observer independently opens the actual file and checks the magic, lengths, payload digests, ordered integrity chain, totals and EOF. It checks status/revision/AUM count, ordered node IDs/keys/rotation keys/historical signatures, secret frames and every ordered AUM against the frozen fixture. Genesis/update/removal heads are independently recomputed with BLAKE2s/base32. The empty-metadata wire deliberately differs from canonical AUM serialization (`fixture.go:53-58`); its exact stored bytes are checked, while its canonical head remains the pinned upstream oracle value. No replacement canonicalizer is added.

## Native evidence and measurements

`evidence/receipt.json` binds the socket qualification source snapshot committed at `e090ab9` and its binaries. Later coordinator extensions have separate receipts; this historical receipt is not relabelled. `mode0.log` through `mode5.log` and `matched-final.log` retain the actual output. `snapshots.json` contains base64 of the actual final snapshot files, with SHA256. The native runner exited 0. The deliberate count control exited 41 at assertion 202. The post-rename variant exited exactly 74 without a response, as required. All other daemon shutdowns are intentional SIGKILL followed by an exact wait-status check.

The final matched run used the same compiler, fixture, two-node/count-two state, request bytes and implicit daemon bounds. Each route has ten warmups and two 100-request batches over fresh serial connections. Samples use monotonic nanoseconds; percentiles are nearest rank. ## Failed attempts and limits

The preserved `observer-wire-hash-failure.log` is a real failed observer run, not a daemon failure: the initial observer incorrectly treated typed-empty-metadata wire bytes as canonical AUM bytes. The fixture generator explicitly documents why they differ. `attempts.txt` records compile/register-pressure repairs and the first runner's end-of-buffer control-marker error. These failures are not counted as killed security mutants.

| Obligation | Disposition |
|---|---|
| Local socket framing, registered relay/key binding, admin enforcement, signed fixture append | Native bounded tests above |
| Remote-principal authentication / Noise / SO_PEERCRED | NOT_RUN; existing adapter/Headscale owner |
| Generic operation-ID dedup, policy epoch and object-version compare | Unsupported by IPC v1; Version is not an epoch, Interactive Head is not a generic grant |
| Original-operand wrapped-quantity semantics | NOT_RUN here; maximum u32 declarations refuse, but the wire cannot reveal a sender's already-wrapped expression |
| Full aggregate durable quotas, competing reservations, unsettled cancellation charges | BLOCKED; BudgetLane helper needs integration inside the existing snapshot writer; no duplicate ledger |
| Whole secret dependency closure and actual public-envelope scheduling | BLOCKED; SecrecyLane and existing scheduler/daemon owners; output-policy results are separate |
| Mid-handler revocation, directory/path substitution, descriptor reuse / swapped resume descriptors | NOT_RUN by this harness; no new owner hook or hostile same-UID simulation is presented as supported authentication |
| Every persistence fault and checksum-valid semantic mutation | NOT_RUN beyond the named seams; existing owner suites remain separate evidence |
| Full crypto/codec vectors, seed fixed point, independent final-source review / clean replay | Not rerun by this lane; parent integration gates |
| Power loss, storage rollback, cross-namespace writers, hostile same-UID/root, kernel compromise, physical timing | Outside this hosted profile |

Same-UID/root actors and provisioned ancestors remain trusted. NodeID denotes an adapter-asserted relay, not necessarily an AUM signer. TKA authenticates signer keys against retained parent state and applies its existing fork choice. Rename is the publication linearization; directory fsync gates acknowledgement. A later recovery fsync does not prove power-loss durability after writeback EIO. No deployment, merge, whole-service secrecy proof or completion of #3/#673 is claimed.

## Actual consumer and imported quantity unit mode

The same coordinator has an explicit second mode, not another test framework:

```sh
sh tools/omc.sh
build/omega-mv/seed/out/omc < qualification/security3/run.om > build/security3-run
chmod 700 build/security3-run
build/security3-run "$PWD/build/omega-mv/seed/out/omc" --consumer-units
```

Run this mode with the **consumer repository as the current directory**. It needs the parent's imported `om/quantity/` fixtures and `cmd/tkad/security3-{quantity,secret}/` files. This qualification-only branch does not pretend those consumer sources exist on the immutable base. The parent may compile this coordinator from its own checkout and execute it with the consumer checkout as cwd.

The coordinator invokes the existing builder, loads its actual `build/tkad.om`, verifies that the complete current `cmd/tkad/main.om` is its exact suffix, and removes only that suffix for fixture composition. Thus the production source list remains owned by `tools/build-tkad.sh`; the coordinator has no second hardcoded production list. It appends the actual owner fixtures, never replicas of handlers or comparators.

All generated files are named `build/security3/unit<PID>-<id>{.om,.log}` or the executable without a suffix, and are created exclusively. Refused compiler output is never executed. Each process status must be the exact expected normal exit, not merely nonzero.

Secret early-return modes1/2 intentionally pass functional tests; this is **not** a leakage-scanner or secrecy pass. Exporter output size is checked by this coordinator, not mistaken for an independent semantic oracle; its exact output hash is recorded separately.
